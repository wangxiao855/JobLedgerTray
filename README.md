# 投递簿 · JobLedger

> 投完 5 秒记一笔，进度不再翻官网。

"我投了好多简历，自己都数不过来了，在招聘软件、在公司官网"、"XX公司XX岗简历流程到哪了"、"乱乱乱"
这是一个本地优先的浏览器扩展：在招聘页一键记录公司、岗位、链接和职位描述，自动生成投递看板。没有账号、没有服务器，数据只保存在当前浏览器里。


![投递看板](tests/dashboard-preview.png)

## 现在能做什么
完成安装后：
- **招聘页一键记录**：公司官网投递成功后，页面右下角出现'记投递'，自动预填公司、岗位、链接和页面标题，确认后保存。
- **投递成功页提示**：页面出现'投递成功 / 申请成功 / 简历已收到'等文案时，弹出'记一笔'提示。
- **干净的单色界面**：白色纸面、浅灰画布、细边框卡片和克制的红色强调，参考 Refero “Ui” 风格；看板、弹窗和图标统一。
- **投递看板**：
  - 列表视图默认**按公司聚合**：先显示公司，点开看该公司下的每个岗位；
  - 每家公司右侧带'邮件情况'栏，按岗位分组显示该公司收到过的邮件和分类；
  - 没有岗位信息的投递流程邮件、信息确认等其他公司邮件，单独放在「其他邮件」栏；
  - 新邮件/状态更新会在公司、岗位邮件组和'其他邮件'上显示红色'新'标记，展开公司后清除；
  - 邮件主题链接到邮箱，岗位的'投递网址'链接到官网/招聘页，两者分开；
  - 列表视图和看板视图随时切换；
  - 搜索公司、岗位、备注、邮件主题；
  - 按'全部 / 进行中 / 面试中 / 待跟进 / Offer / 已结束'筛选；
  - 超过 7 天没更新的记录自动标为'待跟进'；
  - 每个岗位显示'投递网址'，看板卡片上也有'查看投递页'；
  - 状态时间线、编辑、删除；
  - JSON 备份导入导出、CSV 导出。
- **重复岗位提示**：手动新增时，如果公司 + 岗位已经存在，会提示'该岗位已存在'，不会静默合并。
- **可选邮件自动同步**：运行本地托盘服务后，扩展可读取招聘邮件并更新已有投递记录，不需要逐条手动改。邮件不会再自动变成一个个岗位。
- **PDF 附件正文**：招聘通知放在 PDF 附件里时，托盘会提取 PDF 文本并走同一套公司/岗位/状态识别。
- **可选大模型识别**：在'邮件同步'里填自己的 OpenAI 兼容 API Base URL、API Key 和模型名；服务会把招聘邮件正文发给你指定的模型，让它输出固定状态（笔试/面试/Offer/拒绝等）和邮件分类。模型失败时自动回退到关键词规则。
- **默认本地**：不访问云端，不上传页面内容，默认不读取邮箱。只有你主动启用邮件同步后，扩展才会请求本机 `127.0.0.1`；启用大模型后，邮件正文会发送到你自己的模型 API。

## 安装

1. 确认里面有一个完整的 `extension` 文件夹（包含 `manifest.json`）。
2. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`，选择开发者模式。
3. 点击'加载已解压的扩展程序'，选择 `extension` 文件夹。
4. 建议把'投递簿'固定到工具栏。首次安装会自动打开看板。
5. 首次打开插件需要填写相关配置（邮箱授权码与大模型apikey仅存在于你的电脑本地）
6. 打开任意招聘页，右下角会出现'记投递'。安装前已经打开的页面需要刷新一次。
7. 如果要邮件同步，双击 `JobLedgerTray\JobLedgerTray.exe`，托盘图标出现后到看板'邮件同步里填邮箱。

## 使用

### 在招聘页记录

打开职位详情页，点右下角「记投递」。扩展会尝试识别：

- 公司名（优先读 JSON-LD、`og:site_name`、页面 Logo/公司名区域，最后才用域名）；
- 岗位名（优先读 `h1`、职位标题区域、页面标题）；
- 当前链接、页面标题、工作地点、薪资、职位描述摘要。

识别结果可以手动改。保存后点'打开看板'即可看到进度。

### 投递成功页

提交简历后，如果页面出现'投递成功'、'申请成功'、'简历已收到'等文案，扩展会在右下角弹出提示。点'记一笔'确认保存；不确认不会写入任何数据。

### 看板

- 顶部统计卡可以点击筛选；
- 列表默认按公司聚合，点公司行展开该公司的岗位和邮件；
- 公司行右侧显示邮件数量和最近一封邮件，展开后是按时间排列的邮件栏；
- 每个岗位可以在列表里直接改状态下拉框；
- 看板视图按阶段分列，点卡片编辑；
- '待跟进'按最近更新时间计算，默认 7 天；
- '导出'支持 JSON 备份和 CSV 表格；
- 看板地址支持 `?view=board` 直接打开看板视图。

### 邮件自动同步（Windows 托盘版，推荐）

 `JobLedgerTray` 文件夹，打开 `JobLedgerTray.exe`，右下角会出现托盘图标即可，没有页面，不需要开命令行，也不需要单独装 Python。

```text
IMAP 邮箱 → JobLedgerTray.exe（托盘/后台） → http://127.0.0.1:8787 → 扩展看板
```

1. 双击 `JobLedgerTray\JobLedgerTray.exe`，确认右下角出现托盘图标；
2. 打开投递看板 → 右上角'邮件同步'；
3. 填 IMAP 服务器、账号、授权码、文件夹（默认 `INBOX`）；
4. 可选：勾选'用大模型判断邮件状态'，填 API Base URL、API Key、模型名；
5. 点'测试连接'，成功后勾选'启用自动同步'，保存；
6. 如果之前已经用规则同步过，点一次'重新识别邮件'，用当前大模型重新扫描；它会删除自动导入的岗位并重建，手动投递会保留；


首次保存并启用后会自动读取历史邮件：同一公司、同一岗位的多封邮件只生成一条岗位记录；邮件日期会成为「投递」日期，没有邮件的记录才使用你保存时的时间。首次导入默认回溯 365 天、最多 500 封，可以在弹窗里调整。LLM 需要逐封判断，历史邮件多时第一次会比较慢。

## 权限说明

| 权限 | 用途 |
|---|---|
| `storage` | 把投递记录保存在本机 `chrome.storage.local` |
| `activeTab` | 点开弹窗时读取当前标签页的标题和链接 |
| `contextMenus` | 右键菜单「记入投递簿」 |
| `alarms` | 启用邮件同步后，每 5 分钟唤醒 Service Worker 检查一次 |
| `http://*/*`、`https://*/*` | 在招聘页注入右下角按钮，并检测投递成功页 |

扩展默认不访问网络。只有你主动启用邮件同步后，Service Worker 才会请求你填写的本机地址（默认 `http://127.0.0.1:8787`）；不会把页面内容或邮件内容发到云端。页面内容只在本地解析，保存的是公司、岗位、链接、标题、职位描述摘要和你的备注。

## 数据与隐私

- 数据默认只存在当前浏览器配置文件的 `chrome.storage.local` 中。
- 不上传、不卖、不共享；没有账号体系。
- 看板底部「清空全部数据」可以一键删除；卸载扩展也会清除本地数据。
- 建议定期用「导出 → JSON 备份」保存一份，换电脑或重装浏览器时再导入。

## 已知限制

- **邮件同步只覆盖会发邮件的公司**。电话、HR 微信、招聘平台站内信、只更新官网个人中心的情况，还是需要自行查看。
- **邮件同步需要本地服务在运行**。服务停了，自动同步会失败并在看板上显示红色状态点；重新启动服务后点「立即同步」即可恢复。
- **邮箱跳转受服务商限制**。Gmail/Outlook 可以按 Message-ID/主题定位；163/QQ 网页版没有公开的按邮件 ID 深链，当前只能打开邮箱首页。需要精确跳转时，请在邮箱里按主题搜索。
- **不自动同步公司招聘系统的状态**。它记录的是「你投了什么」，不是「公司内部走到哪一步」。状态以你的手动更新和邮件/短信通知为准。
- **成功页识别是启发式的**。不同公司页面差异很大，扩展会尽量识别，但保存前需要你确认。
- **公司/岗位识别可能不准**。尤其是自定义官网、共用 ATS 域名的页面；识别结果都可以编辑。
- **大模型是可选的，且会把邮件正文发给你填的 API**。API Key 只存本机 `%LOCALAPPDATA%\JobLedger\config.json`，但邮件内容会离开这台电脑，请确认你信任该模型服务商。
- **大模型必须是 OpenAI 兼容接口**。Base URL，例如 `https://api.deepseek.com/v1`。
- **不会自动登录、不会代填、不会自动投递**。它只做记录和跳转。
- **仅支持 Chromium 浏览器**（Chrome、Edge 等）；不支持 Firefox、Safari。
- 数据不跨设备同步；多台电脑请用 JSON 导入导出。
- 职位描述摘要会截断到 3000 字，避免本地存储膨胀。
